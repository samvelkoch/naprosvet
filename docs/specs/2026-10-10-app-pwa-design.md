# Приложение «На_просвет», этап A: PWA. Дизайн-спека

Дата: 2026-10-10. Статус: на согласовании.

## 1. Цель и границы

**Зачем.** Привычка и возврат. Часть читателей удобнее запускать приложение с иконкой, чем ходить на сайт. Приложение должно давать повод открыть его завтра.

**Что внутри.** Три исследования целиком («Бродский на просвет», «Чехов на просвет», «Ромен Гари на просвет») и «Голоса_» на равных. Новых авторов не планируется; рост содержания идёт новыми вопросами в опросниках «Голосов».

**Критерий «сработало».** Измеряется счётчиком (раздел 9). Целевые значения доли вернувшихся через 7 и 30 дней фиксируются после первого месяца данных, не раньше.

**Не входит в этап A.** Магазины приложений (этап B, оболочка Capacitor на том же коде). «Спросить своё» у живой персоны (этап C, отдельное решение: сервер, оплата ответов, модерация). Аккаунты и синхронизация между устройствами: всё хранится на устройстве. Изменения в содержании исследований и ответах «Голосов».

## 2. Архитектура: приложение = сайт в режиме standalone

Отдельного приложения-оболочки нет. Страницы остаются самодостаточными HTML из генераторов авторов. Добавляется общий слой, как уже сделано с `theme.js`:

| Файл | Назначение |
|---|---|
| `manifest.webmanifest` | имя «На_просвет», `start_url: /today/`, `display: standalone`, цвета `--desk` и `--page`, иконки 192/512 (maskable) из `favicon.svg`, скриншоты для расширенного диалога установки на Android |
| `sw.js` | сервис-воркер: предкэш и стратегии обновления (раздел 6) |
| `app.js`, `app.css` | нижняя навигация, оглавление исследований, «сохранить» и «поделиться» на ответах, календарь отметок, регистрация SW, подсказка установки |
| `today/` | экран «Сегодня» (раздел 4), `today/build.py` → `today/cards.json` |
| `shelf/` | экран «Полка» (раздел 5) |
| `worker/` | Cloudflare Worker: события счётчика и рассылка пушей (разделы 8 и 9), под-этап A1 |

Подключение в страницы авторов: обёртки генераторов (`brodsky/analysis/wrap_pages.py`, `gary/analysis/wrap_site.py`, `chekhov/analysis/wrap_site.py`) берут `<head>` из уже опубликованного `index.html` на сайте. Поэтому `<link rel="manifest">`, `app.css` и `app.js` добавляются прямо в три `index.html` в `naprosvet-site`, а генераторы подхватывают их при следующей пересборке. Репозитории авторов не меняются. Главная, `voices/`, `today/`, `shelf/` подключают то же.

Данные «Сегодня» и «Полки» берутся из `voices/data.json`; `voices/build.py` не меняется, кроме экспорта фиксированной перестановки вопросов для «вопроса дня» (раздел 4).

## 3. Навигация

Нижняя панель из четырёх вкладок на всех страницах: **Сегодня · Голоса_ · На_просвет · Полка**. «На_просвет» ведёт на главную с тремя исследованиями. Панель показывается только на узких экранах (до 768 px) или в standalone-режиме; на десктопе сайт выглядит как сейчас. Подписи текстом в моно-шрифте, без иконок из библиотек.

**Вкладка «На_просвет».** Три исследования списком: название, объём («30 разделов · 561 стихотворение»), строка «Продолжить с III.2 Словоискатель», если страницу уже открывали. Ниже «На просвет сегодня» за последние дни. Страницы исследований открываются как есть: это тот же HTML, что на сайте, со всеми разделами, графиками и интерактивами, ничего не вырезается и не упрощается.

**Оглавление исследований.** На страницах авторов боковая рейка разделов (`nav.rail`) на телефоне скрыта. `app.js` добавляет кнопку «Оглавление» в нижнюю панель, когда открыта страница автора: выезжающий лист с частями и разделами по существующим `section[id]` и `h2`. При открытии страницы восстанавливается последнее место («Продолжить с III.2 Словоискатель»), позиция пишется в localStorage при прокрутке.

Глубокие ссылки: разделы по `#id` (уже работают), вопросы «Голосов» по `#<id вопроса>` (страница уже читает `location.hash`).

## 4. Экран «Сегодня»

**Вопрос дня.** Один на всех: номер дня от даты запуска (задаётся в конфиге) по фиксированной перестановке 300 вопросов, которую экспортирует `build.py` в `data.json` (`order`). Через 300 дней перестановка идёт по второму кругу; к этому времени ожидаются новые вопросы.

**Состав экрана сверху вниз.**
1. Дата и «спрашивает <составитель> · <раздел опросника>» (моно).
2. Вопрос крупно (serif).
3. Три ответа, свёрнутые до первой фразы, с именем автора и точкой его времени («Венеция, ноябрь 1993»). Касание разворачивает ответ целиком.
4. Под развёрнутым ответом: «Открыть в Голосах_ →» (глубокая ссылка) и, если есть, ссылка в исследование по теме вопроса (ручная таблица тема → раздел автора, `today/links.json`; при отсутствии записи ссылки нет).
5. Строка действий: «Чей ответ?», «Сохранить», «Поделиться».
6. **«На просвет сегодня»**: одна карточка из исследований, по очереди от трёх авторов: миф или факт (вопрос, затем вердикт с числом), рекорд, слово дня с кривой по эпохам. Карточка ведёт в свой раздел исследования по `#id`. Данные извлекаются при сборке скриптом `today/build.py` из JSON внутри трёх `index.html` (ключи `myths`, `records`, слова эпох) в `today/cards.json`; генераторы авторов не меняются. Так исследования участвуют в ежедневной привычке, а не только лежат во вкладке.
7. Стрелка к предыдущим дням, до 30 назад; вперёд нельзя.

**Без мелких портретов.** На экранах приложения автор обозначается именем в моно-шрифте и терракотовой линией, без уменьшенных рисунков: мелкие портреты удешевляют дизайн (решение пользователя 2026-10-10). Живые портреты остаются на первых экранах страниц авторов.

**Отбор для «Чей ответ?» дня.** Анонимно показывается только ответ, в первых двух фразах которого нет имени автора, его псевдонимов и городов его жизни (Ленинград, Петербург, Венеция, Таганрог, Ялта, Вильно, Ницца, Париж); список маркеров в конфиге, проверка при сборке. Если ни один из трёх ответов не проходит, мини-игры в этот день нет.

**«Чей ответ?» на «Сегодня».** Показывается один из трёх ответов без имени, три кнопки с именами, после выбора ответ: верно или нет, и счёт «N из M за неделю». Один раз в день. Полная игра сериями по 10 остаётся в «Голосах_» как есть.

**Поделиться.** Карточка PNG через canvas: вопрос, один ответ (обрезка по длине с многоточием), имя автора, подпись «на_просвет» с подчёркиванием. Отправка через Web Share API с файлом; где файлы не поддерживаются, скачивание PNG.

**Сохранить.** Кладёт ответ в «Полку» (localStorage: id вопроса, автор, дата).

## 4а. Вкладка «Голоса_»

Страница `/voices/` открывается как есть, целиком: барабан вопросов с ручкой-рычагом, «Читать» и «Чей ответ?» с серией из 10, фильтр «спрашивает», выбор вопроса из списка и по теме, «Как сделаны голоса». Ничего из этого не переделывается и не упрощается под телефон сверх того, что страница уже умеет. `app.js` добавляет только нижнюю панель, кнопки «Сохранить» и «Поделиться» на каждом ответе и переход по глубокой ссылке с «Сегодня» и из «Полки». Ручка барабана на телефоне уже видна и работает (проверено на эскизе: полоса 48 px справа от барабана, нажатие запускает вращение).

Два места, где страница и приложение накладываются, решаются в `app.css` только в standalone-режиме:
- **Шапка страницы** «← На_просвет» с кнопками «!» и «☾» скрывается: назад ведёт вкладка «На_просвет», переключатель темы живёт в «Полке», дисклеймер «!» остаётся доступным внутри страницы в «Как сделаны голоса».
- **Нижняя панель страницы** («☰ · Крутить барабан») остаётся, потому что без неё не покрутить барабан, и стоит над панелью вкладок. Чтобы две панели не съедали экран, панель вкладок на вкладке «Голоса_» прячется при прокрутке вниз и возвращается при прокрутке вверх.

## 5. Экран «Полка»

- Календарь месяца из точек: день, в который открывали «Сегодня» или любую страницу приложения, отмечается терракотовой точкой. Без серий, очков и напоминаний «не прервите цепочку».
- Список сохранённых ответов: вопрос мелко моно, первая фраза serif, имя; касание ведёт в «Голоса_» на вопрос. Фильтр по автору.
- Настройки: тема (уже есть в `theme.js`), время пуша, «Установить на экран» (раздел 7), «Очистить сохранённое».

## 6. Офлайн и обновления

**Предкэш при установке:** главная, `today/`, `shelf/`, `voices/index.html`, `voices/data.json`, `brodsky/`, `chekhov/`, `gary/` (три `index.html`), `theme.js`, `app.js`, `app.css`, иконки. Итого около 14 МБ. Шрифты с Google Fonts кэшируются при первом запросе; офлайн без них работают резервные Georgia и системный моно.

**По запросу:** видео живых портретов (`portrait.webm`/`.mp4`, по 1,4 МБ) кэшируются после первого просмотра.

**Стратегии:** HTML и `data.json` — показать из кэша, обновить в фоне (stale-while-revalidate); при обновлении ненавязчивая плашка «Есть новая версия, обновить». Статика с версией в имени — только кэш.

**Хранилище устройства:** localStorage для сохранённого, календаря, позиций чтения, настроек. Ограничение не ожидается (единицы КБ).

## 7. Установка

- Android (Chrome): перехват `beforeinstallprompt`, своя кнопка «Установить» на главной и в «Полке»; системный диалог с иконкой и скриншотами.
- iPhone (Safari): установка только через «Поделиться → На экран „Домой“». Один раз показывается подсказка с этой последовательностью, закрывается навсегда.
- Первый запуск в standalone: один раз экран с текстом из «Как сделаны голоса» о том, что ответы — реконструкция, а не цитаты.

## 8. Пуш (под-этап A1)

Web Push требует сервера для отправки: GitHub Pages его не даёт. Используется Cloudflare Worker (бесплатный тариф): подписки хранятся в KV с выбранным часом; крон раз в час шлёт вопрос дня тем, у кого наступил выбранный час. Текст пуша — сам вопрос, нажатие открывает `today/`. Ключи VAPID в секретах Worker. Разрешение на пуш запрашивается после третьего открытого «Сегодня», не при первом запуске. На iPhone пуш работает только для установленного приложения (iOS 16.4+). Этап A0 выпускается без пуша.

## 9. Счётчик

На всех страницах уже стоит Яндекс.Метрика (счётчик 113309794, вебвизор включён). Отдельный счётчик не нужен.
- Просмотры и возвраты: стандартные отчёты Метрики «Новые и вернувшиеся посетители», срез по признаку standalone (параметр визита `app=1`, который `app.js` передаёт через `ym(..., 'params')` при открытии в установленном приложении).
- События приложения через `ym(..., 'reachGoal', имя)`: `app_install`, `today_open`, `answer_open`, `guess_ok`, `guess_fail`, `save`, `share`, `toc_open`.
- Текст о сборе данных уже уместен на странице «Как сделаны голоса»; дополняется строкой о Метрике.

## 11. Проверка перед сдачей

- Lighthouse: приложение устанавливаемо; без сети открываются все четыре вкладки и три исследования.
- Установка на Android (Chrome) и iPhone (Safari 17): иконка, standalone, safe-area снизу.
- Размер предкэша не больше 15 МБ; обновление страницы автора после пересборки доезжает без переустановки.
- Карточка «поделиться» уходит в Telegram с iPhone и Android.
- Тёмная и светлая темы на всех новых экранах.
- Генераторы авторов: диф страниц только подключение манифеста, `app.css` и `app.js`; сверка панелей книги не ломается.

## 12. Открытые вопросы

1. Аккаунт Cloudflare для Worker (A1): чей и когда. Нужен только для пуша.
2. Дата старта отсчёта «вопроса дня».
3. Таблица тема → раздел исследования: составить вручную при реализации (10 тем × 3 автора), допускаются пропуски.
